# TEAM 친선경기 호스트 팀 명단 계약

> 최신 사용자 정정: 주최 권한과 실제 참가는 별개다. 주최 측 명단에는 실제 참가자를
> 명시하고 주최자를 자동 추가하지 않는다. capacity는 팀당 최대 인원이며 5대5는 5다.
> 사용자는 0명 명단도 확정 가능하며 상대 승인 전 명단 확정 조건을 충족한다고 선택했다.
> 생성 시 생략/null은 미확정, PUT 시 생략/null은 400이며 명시적 []과 구분한다.

2026-11-24 사용자 정정과 승인 정책을 기록한다. 이 문서는 승인된 정책과
아직 승인되지 않은 API 제안을 구분하며, 제안만으로 구현을 승인하지 않는다.

후속 사용자 지시인 "일단 진행해"로 아래 생성 선택 필드와 주최자 전용 PUT 경로의
기본 형태를 승인받았다. 세부 미결정 정책까지 일괄 승인받았다는 뜻은 아니다.

## 승인된 정책 (APPROVED)

- TEAM은 호스트 한 팀과 상대 한 팀으로 구성된다.
- `capacity`는 **각 팀의 최대 인원**이다. 5대5의 값은 5이며 10이 아니다.
  현재 명단 인원수와 별도 값이다. 주최자는 실제 참가할 때 명단에 명시하며 자동으로
  인원에 더하지 않는다. 상대 팀 대표자 처리 정책은 이번 정정으로 변경하지 않는다.
  정확히 capacity명으로 채우거나 양 팀 인원이 같아야 하는지는 아직 확정하지 않았다.
- 경기 생성 시 호스트 팀 명단을 몰라도 된다. 명단 미확정 상태에서도 상대 팀의
  참가 신청을 받을 수 있다. 단, 상대 팀 참가 신청을 승인하기 전에는 호스트 팀
  명단을 확정해야 한다.

TEAM의 capacity는 팀별 최대 인원이며 INDIVIDUAL의 capacity는 경기 전체 실제 참가자의
최대 인원이다. 개인전은 2026-11-24 후속 사용자 답변으로 확정했다. 어느 경우에도
주최자 자체를 자동으로 합산하지 않는다. 실제 참가자로 명시했을 때만 센다.

## 기본 API 형태 — 진행 승인

생성 선택 필드 `hostTeamMemberIds`와
`PUT /friendly-matches/{matchId}/host-roster` 기본 형태로 테스트를 시작한다.
주최 측 명단은 실제 참가자 전체를 명시하며 주최자도 직접 뛸 때만 포함한다.
JWT 사용자와 실제 경기 주최자를 대조하는 관리 권한 검사는 유지한다.
구체적인 내부 상태 표현, 빈 명단의 확정 처리와 미결정 사항은 아래 구분을 유지한다.

### 생성 요청 확장

- 선택 필드 `hostTeamMemberIds`로 주최 측 실제 참가자 전체를 전달한다.
  주최자의 게임 프로필을 자동 추가하거나 반드시 제외하지 않는다.
- 필드 생략 또는 `null`은 `UNCONFIRMED`로 표현한다.
- 목록이 제공되면 검증을 통과한 명단을 `CONFIRMED`로 표현한다.
- 빈 목록 `[]`은 실제 참가자 0명의 확정 명단으로 허용한다. 상대 승인 전 주최 명단
  확정 조건을 충족한다. capacity를 0으로 바꾸거나 주최자 1명을 자동 합산하지 않는다.
  이는 2026-11-24 사용자의 명시적 선택이며 추가 목록 검증 정책과 구분한다.

### 명단 확정 API

- `PUT /friendly-matches/{matchId}/host-roster`로 명단 전체를 교체한다.
- JWT 인증 사용자와 실제 경기 호스트를 확인한다.
- 요청 본문의 `teamMemberIds`는 필수이며 생략/null은 400이다.
  실제 참가자 전체를 전달하고 빈 목록 `[]`은 0명 확정으로 허용한다.
- 성공 응답은 `200`과 기존 경기 응답 형식을 기준으로 테스트를 시작한다.
  새 확정 상태, 인원수, 프로필 ID 목록 등의 추가 공개 필드는 아직 정하지 않았다.

프로젝트 탐색에서 기존 호스트 명단 PUT 계약을 찾지 못했다. 따라서 위 경로는
  과거부터 존재한 계약으로 취급하지 않는 **이번 신규 API**다.

## 미결정 사항 (OPEN)

- 추가 응답 필드. Controller 테스트는 기존 경기 응답의
  id/capacity와 공통 성공 형식을 기준으로 시작하며 새 공개 필드를 임의로 고정하지 않는다.
- 상대 팀 참가 승인 후 호스트 명단 변경 허용 여부와 처리 방식.
- 양 팀에 동일한 사람이 포함되는 경우의 허용 여부와 검증 방식.
- 최대 인원 검사와 오류 응답은 후속 승인으로 확정했다. 명단은 저장 전에 검증하며
  중복/다른 게임/정원 초과는 400, 없는 프로필은 404다. 아래 최신 검증 기록을 따른다.
- 명단 확정·교체와 상대 팀 참가 승인이 동시에 발생할 때의 처리 정책.

미결정 사항을 추정하여 구현하지 않는다. 정확히 capacity명 또는 동일 인원의
완성된 N:N 팀을 요구하는 최소 인원·충원 조건을 추가하지 않는다.

존재나 승인 근거가 아니다.

스키마 변경을 요구하지 않는다. 이 문서 작업에서는 백엔드 코드를 변경하지 않는다.
