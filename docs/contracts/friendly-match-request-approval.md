# 참가 신청 승인 계약

2026-11-25. 사용자가 제안된 계약에 대해 진행을 승인한 정책이다.
Jira와 Notion 원문은 연결 권한 및 조회 문제로 이번에 재확인하지 못했다.
아래 내용을 과거 원문의 재검증 결과로 취급하지 않는다.

## 요청과 성공 응답

- `PATCH /match-requests/{requestId}/status`
- JWT 인증 필수, 경기 주최 프로필의 실제 소유 사용자만 승인 가능하다.
- 양수 신청 ID와 JSON `{"status":"APPROVED"}`를 받는다.
- 거절, 취소와 클럽 운영진 권한은 이번 범위 밖이다.
- 200과 기존 공통 응답 형식을 사용한다. data는 requestId, matchId,
  status와 participantGameUserIds이며 목록은 해당 신청의 실제 참가자 전체다.

## 참가 명단과 정원

- 신청 대표 gameUserId와 추가 teamMemberIds 전원이 실제 참가자다.
- 주최자는 주최 명단에 직접 포함된 경우만 참가자로 계산한다.
- 주최 명단은 확정되어야 하며 명시적 빈 명단도 확정된 0명으로 허용한다.
- TEAM의 capacity는 팀별 최대 인원이다. 상대 신청 한 건만 승인하고,
  양 팀은 각각 capacity 이하면 된다. 정확한 충원과 동일 인원은 요구하지 않는다.
- INDIVIDUAL은 주최 명단, 기존 승인 참가자와 새 신청 참가자를 합산해
  경기 전체 capacity 이하인지 확인한다.
- 명단 내부 또는 주최 명단과 기존 승인 참가자 사이의 중복은 거부한다.
- 실제 참가 프로필의 존재와 경기 게임 일치를 승인 전에 검사한다.

## 상태와 동시 요청

- PENDING만 새롭게 APPROVED로 전환한다.
- TEAM은 상대 승인 시, INDIVIDUAL은 전체 정원 도달 시
  RECRUITMENT_CLOSED로 전환한다. 다른 대기 신청은 보존한다.
- 같은 신청의 재승인은 주최 권한 확인 후 200이며 참가자를 중복 저장하지 않는다.
  모집 종료 여부 때문에 재승인이 실패하지 않는다.
- CANCELLED나 REJECTED 신청 승인은 409다.
- 현재 승인 기록이 있으면 주최 명단 교체는 409로 거부한다. 빈 명단 교체도 같다.
  모집 중인 개인전에도 적용하며 권한 검사가 충돌 검사보다 먼저다.
- 승인과 주최 명단 변경은 같은 경기 행의 비관적 잠금에 참여한다.
  신청 상태 변경, 실제 참가자 저장과 모집 상태 변경은 같은 트랜잭션이다.

## 오류 응답

| 상황 | 응답 |
| --- | --- |
| 입력 오류 | 400 COMMON_400 |
| 미인증 | 기존 인증 401 |
| 주최 권한 없음 | 403 AUTH_403 |
| 신청 없음 | 404 MATCH_REQUEST_001 |
| 경기 없음 | 404 FRIENDLY_MATCH_001 |
| 프로필 없음 | 404 GAME_USER_001 |
| 명단 미확정, 정원 초과, 참가 중복, 상태 충돌 | 409 MATCH_REQUEST_004 |
| 모집 종료 | 기존 409 MATCH_REQUEST_003 |
| 승인 후 주최 명단 변경 | 409 FRIENDLY_MATCH_002 |

오류 코드 번호는 기존 목록과 대조하여 배정한 구현 식별자다. 업무 예외 메시지는
구체적인 실패 이유를 보존한다. 모집 종료 상태에서 다른 TEAM 신청을 승인하면
검사 순서에 따라 기존 모집 종료 코드가 반환된다.

## 후속 범위

클럽 운영진의 역할 모델, 승인 취소 이후 명단 변경 정책, 정원과 경기 속성 수정,
MySQL 런타임과 부하 성능 및 FIFO 보장은 별도 범위다.

실행 및 종료 리뷰 증거는 [승인 API 종료 검토](../match-request-approval-api-end-review.md)에 기록한다.
